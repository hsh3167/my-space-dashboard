# 자산관리 개발 계획과 검증 기록

기존 개인용·업무용·AI 사무실과 링크 저장/백업은 유지한다. 자금 확보 시뮬레이터는 범위에서 제외한다. 공개 저장소에는 합성 샘플과 테스트만 넣는다.

1. `feat: add sample asset management workspace`: 기존 다크 테마에 자산관리 작업 공간, 총자산/순자산, 계좌 구성, 보유종목, 월별 그래프, 주택 납부 일정을 추가한다. 집계·차트·기존 링크 기능 회귀 테스트 후 커밋한다.
2. `feat: secure asset workspace with Supabase auth and RLS`: 자산 화면에만 이메일/비밀번호 로그인을 적용한다. 세션은 메모리에만 두며 로그인/허용 사용자 확인 전에 금융 테이블을 조회하지 않는다. 본인 UUID 한 명만 DB에서 허용하고 모든 테이블에 RLS를 적용한다. 실제 PostgreSQL 엔진 기반 정책 테스트, 가짜 응답 기반 인증 경계 테스트 후 커밋한다.
3. `feat: import Samsung Securities CSV and XLSX safely`: 로컬 파일 파싱, 일반/퇴직연금 구분, 자동/수동 매핑, 미리보기/검증, 서버 측 원자적 중복 방지를 구현한다. 원본 파일·파일명·계좌번호·주민번호는 저장하지 않는다. 합성 파일로 파싱/업로드 테스트 후 커밋한다.

브라우저 검증은 사용자 지정 EGO-LITE에서만 진행한다. 현재 연결 도구/실행 경로가 제공되지 않아 연결을 요청했다. 다른 브라우저로 대체하지 않는다. Node 테스트/DOM 회귀 테스트와 HTTP 검증은 독립적으로 진행한다.

외부 선행 작업: Supabase 프로젝트 및 본인 Auth 계정 생성, SQL 마이그레이션 실행, 사용자 UUID 허용 등록, 공개 URL/publishable 키 설정. 비밀 키는 프런트엔드·Git에 넣지 않는다. GitHub Pages 게시 후 기존 탭과 자산 탭을 다시 검증한다. 실제 금융정보는 모든 테스트를 통과하고 사용자가 연결을 완료하기 전까지 사용하지 않는다.

실행 결과와 남은 외부 작업은 각 단계에서 이 문서 및 설정 가이드에 기록한다.

## 1단계 검증

`npm test`: 7개 통과 (집계/차트/출력 이스케이프 및 기존 탭·검색·링크 생성/수정/삭제·백업·딥링크 DOM 회귀). `node --check app.js`, `git diff --check` 통과. 실제 브라우저/모바일 렌더링은 EGO-LITE 연결 전이므로 미검증.

## 2단계 검증

인증 전/다른 사용자/익명 금융 조회 차단, 로그아웃 중 지연 응답 무효화, 비밀 키 거부 및 DOM 로그인 경계 테스트 추가. PGlite의 PostgreSQL 엔진에서 실제 마이그레이션/RLS 정책을 실행했다. `npm test`: 19개 통과. 실제 Supabase 프로젝트/계정이 없어 호스팅 DB·실제 Auth 검증은 미실행. EGO-LITE 검증도 연결 대기. 사용자 외부 설정 절차는 `docs/supabase-setup.md` 참조.
